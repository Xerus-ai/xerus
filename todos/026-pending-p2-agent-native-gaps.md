# P2: Agent-Native Parity Gaps — Orphan Features and Template Divergence

## Problem Statement

Three agent-native parity issues where agents cannot do what users can:

1. **Project overview orphan**: `GET /domains/:id/overview` returns aggregated dashboard data. No platform tool equivalent exists for agents.

2. **Scaffolding gap**: `scaffoldChannel()` and `scaffoldProject()` only fire from REST routes. Agent-created channels via `create_channel` platform tool don't get filesystem structure (CLAUDE.md, context.md, etc.).

3. **Template divergence**: 5 new `.tmpl` files (OPERATING.md, RULES.md, agent.yaml, good-outputs.md, knowledge-index.yaml) are never wired into the backend scaffold pipeline. Agents get backend-generated versions which are structurally different (and less rich for OPERATING.md).

## Findings

### workspace-scaffold.service.ts — only imported by company.routes.ts
Platform tool executors don't call scaffold functions.

### OPERATING.md.tmpl vs operating-md.template.ts
Template version has: TeamCreate, TaskCreate, SendMessage, coordination messages, shift handoffs, channel lead duties.
Backend version has: behavior mode, delegation, skills-first workflow. Missing all coordination primitives.

### agent.yaml.tmpl, RULES.md.tmpl, good-outputs.md.tmpl, knowledge-index.yaml.tmpl
Never generated by `scaffold-payload.service.ts`. Agents don't get these files.

## Proposed Solutions

1. Add `scope: 'domain'` to `get_status` platform tool for project overview data
2. Call `scaffoldChannel()`/`scaffoldProject()` from platform tool executors
3. Merge OPERATING.md.tmpl content into `operating-md.template.ts`
4. Add RULES.md, good-outputs.md, knowledge-index.yaml to scaffold-payload

## Acceptance Criteria
- [ ] Agents can access project overview data via platform tools
- [ ] Agent-created channels get same filesystem structure as UI-created ones
- [ ] All template files are wired into the backend scaffold pipeline
